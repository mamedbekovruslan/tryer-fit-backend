## Что такое NestJS?

NestJS - это прогрессивный **фреймворк Node.js** для создания эффективных, надежных и масштабируемых серверных приложений. Он использует современный JavaScript и создан с использованием **TypeScript** (сохраняя совместимость с обычным JavaScript) и сочетает элементы **Объектно-ориентированного программирования (ООП)**, **Функционального программирования** и **Функционального реактивного программирования**.

### Ключевые особенности NestJS:
- **Модульность**: Организует код в повторно используемые модули
- **Внедрение зависимостей**: Автоматически управляет созданием объектов и зависимостями
- **Декораторы**: Использует декораторы TypeScript для метаданных и конфигурации
- **Масштабируемость**: Создан для корпоративных приложений
- **Совместимость с Express/Fastify**: Работает как с Express.js, так и с HTTP-серверами Fastify

## Архитектурные концепции

NestJS следует модульной архитектуре с несколькими ключевыми концепциями:

### 1. Модули (`@Module`)
- Модули - это классы, помеченные декоратором `@Module`
- Они предоставляют метаданные, которые говорят Nest, как организовать приложение
- Каждый модуль группирует связанные компоненты вместе
- Каждое приложение Nest имеет хотя бы один корневой модуль (в данном случае `AppModule`)

### 2. Контроллеры (`@Controller`)
- Контроллеры обрабатывают входящие запросы и возвращают ответы клиенту
- Они определяют маршруты и HTTP-методы (GET, POST, PUT, DELETE и т.д.)
- В нашем примере `AppController` имеет один маршрут для корневого пути `/`

### 3. Сервисы/Провайдеры (`@Injectable`)
- Сервисы содержат бизнес-логику, которую могут использовать контроллеры
- Они внедряемые (injectable) и могут совместно использоваться между контроллерами
- В нашем примере `AppService` предоставляет метод `getHello()`

### 4. Декораторы
- Особенности TypeScript, которые позволяют связывать метаданные с нашим кодом
- Примеры: `@Controller()`, `@Get()`, `@Module()`, `@Injectable()`, `@Post()`
- Декораторы являются основой того, как NestJS понимает ваше приложение

## Как работает этот проект

При запуске приложения происходит следующее:

1. **main.ts** запускает приложение и создает экземпляр модуля `AppModule`
2. **app.module.ts** регистрирует контроллеры и провайдеры (сервисы)
3. **app.controller.ts** обрабатывает HTTP-запросы, получая данные от сервиса
4. **app.service.ts** предоставляет бизнес-логику для контроллера

Когда вы посещаете `http://localhost:3000`, происходит следующий процесс:
- Запрос направляется в `AppController`
- Контроллер вызывает метод `getHello()` из `AppService`
- Сервис возвращает строку "Hello World!"
- Эта строка отправляется обратно клиенту

## Основные файлы проекта

### `main.ts` - Точка входа
```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```
- Создает экземпляр приложения NestJS с использованием `AppModule`
- Запускает сервер на порту 3000 или на порту из переменной окружения `PORT`
- Это место, где начинается выполнение вашего приложения

### `app.module.ts` - Корневой модуль
```typescript
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';

@Module({
  imports: [],                  // Импортированные модули
  controllers: [AppController],  // Регистрация контроллеров
  providers: [AppService],      // Регистрация сервисов
})
export class AppModule {}
```
- Это корневой модуль, который говорит NestJS, как собрать приложение
- Регистрирует `AppController` и `AppService`
- Позволяет NestJS знать, какие компоненты используются в приложении

### `app.controller.ts` - Контроллер приложения
```typescript
import { Controller, Get } from '@nestjs/common';
import { AppService } from './app.service';

@Controller()
export class AppController {
  constructor(private readonly appService: AppService) {} // Внедрение зависимости

  @Get()  // Обрабатывает GET-запросы к корню '/'
  getHello(): string {
    return this.appService.getHello();
  }
}
```
- Контроллер обрабатывает HTTP-запросы
- Использует внедрение зависимостей для получения `AppService`
- Метод `getHello()` отвечает на GET-запросы к корневому пути

### `app.service.ts` - Сервис приложения
```typescript
import { Injectable } from '@nestjs/common';

@Injectable()
export class AppService {
  getHello(): string {
    return 'Hello World!';  // Возвращает приветствие
  }
}
```
- Сервис содержит бизнес-логику приложения
- Отмечен декоратором `@Injectable()`, что делает его доступным для внедрения зависимостей
- Предоставляет методы, которые могут использоваться контроллерами

### `app.controller.spec.ts` - Тесты для контроллера
```typescript
import { Test, TestingModule } from '@nestjs/testing';
import { AppController } from './app.controller';
import { AppService } from './app.service';

describe('AppController', () => {
  let appController: AppController;

  beforeEach(async () => {
    const app: TestingModule = await Test.createTestingModule({
      controllers: [AppController],
      providers: [AppService],
    }).compile();

    appController = app.get<AppController>(AppController);
  });

  describe('root', () => {
    it('should return "Hello World!"', () => {
      expect(appController.getHello()).toBe('Hello World!');
    });
  });
});
```
- Тесты проверяют, что метод `getHello()` возвращает правильное значение
- Используется библиотека Jest для тестирования
- `beforeEach` - настройка тестовой среды перед каждым тестом

## Начало работы

- Node.js (версия >= 18.x)
- npm или yarn

1. Убедитесь, что вы в директории `tryer-fit-backend`

```bash
npm install
```

## Запуск приложения

### Режим разработки
```bash
npm run start:dev
```
- Запускает сервер в режиме слежения (автоматически перезапускается при изменениях)
- Сервер запускается на `http://localhost:3000`
- Для остановки используйте `Ctrl+C`

### Режим отладки
```bash
npm run start:debug
```
- Запускает приложение с поддержкой отладки
- Позволяет подключиться отладчику (например, в VSCode)

### Режим продакшн
Сначала соберите приложение:
```bash
npm run build
```

Затем запустите собранную версию:
```bash
npm run start:prod
```

### Тестирование приложения
После запуска сервера посетите `http://localhost:3000` в вашем браузере или выполните GET-запрос, чтобы увидеть сообщение: `"Hello World!"`

## Понимание маршрутов

Текущая установка включает простой GET-маршрут:
- **Маршрут**: `GET /` (корневой путь)
- **Ответ**: Простой текст "Hello World!"

- **Реализация**: Контроллер использует метод из сервиса для получения текста

## Следующие шаги

Для будущей разработки вы можете:

1. **Добавить новые маршруты**:
   - Использовать декораторы `@Post()`, `@Put()`, `@Delete()`, `@Patch()` для различных HTTP-методов
   - Определить параметры маршрутов с помощью `@Param()`
   - Обрабатывать тело запроса с помощью `@Body()`
   - Получать параметры запроса с помощью `@Query()`

2. **Создать дополнительные модули и контроллеры**:
   - Разделить функциональность на логические блоки
   - Пример: пользовательский модуль, модуль товаров, модуль заказов

3. **Интегрировать базу данных**:
   - Использовать TypeORM или Mongoose для работы с базой данных
   - Создавать модели/сущности для хранения данных

4. **Добавить валидацию**:
   - Использовать библиотеки валидации для проверки входящих данных
   - Создавать DTO (Data Transfer Objects) для типизации запросов/ответов

5. **Реализовать аутентификацию и авторизацию**:
   - Добавить защиту маршрутов
   - Реализовать системы входа и регистрации

6. **Добавить middleware**:
   - Обработка логирования
   - Обработка CORS
   - Аутентификация на уровне приложения

7. **Настроить конфигурацию**:
   - Использовать модуль конфигурации для управления переменными окружения
   - Организовать настройки приложения
